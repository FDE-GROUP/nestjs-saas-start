    Class DeleteOrganizationPermanentlyCommandHandler

    硬删租户 handler（NFR-6 删除半·FR-6·平台级）：前置闸仅 tenant.status=deleted 终态可消灭， 先补删事件后连带清除该租户名下所有组织 + 租户本体。

    Remarks

    治理台改锚 tenant（rehierarchy 片一）：作用对象从单组织升为租户——findTenantDetail 一次取准入态（前置闸） 与名下组织名册（事件双维补删：tenant 聚合下 tenantId + 每 orgId·沿假设④）。前置闸（甲裁·两段式 先软后硬，误删 active 无回退路径）；先补删事件、后连带删主行（顺序理由见 command 注释）。#2 甲档收口 （module-p0-async-boundary-correctness 切片 D）：①补删与 ②连带删包单一 uow.run 同事务原子——二者适配器均 mikro.fork()（ALS 感知·事务内复用同一事务 em），故 ②失败/中途抛错 → ①事件删除一并回滚，闭死「主行已没、 事件残留」的孤儿事件窗口（PIPL 不留残迹）；回滚后仍在可整请求重试。EVENT_STORE 直注不受 EVENT_PUBLISH_MODE 开关控制——表在就要清（同 user 硬删先例·S9 教训「显式 @Inject + 值导入」）。审计落 pino（库外幸存·乙裁）。
