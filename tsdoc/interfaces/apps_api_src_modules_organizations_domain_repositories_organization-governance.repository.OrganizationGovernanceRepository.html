    Interface OrganizationGovernanceRepository

    平台租户治理仓储端口（domain-owned · global-tenancy S5 · FR-6）。

    Remarks

    跨租户运营视图的唯一数据卡点：仅经 PlatformOperatorGuard 裁决后的平台级查询/治理 使用——刻意不做租户过滤（平台级天然跨租户，FR-11①），因此该 port 绝不允许被 租户级切片引用（守卫在 controller 逐路由接线，fail-closed）。

    状态迁移（approve/suspend/resume/delete）不在此 port——统一走 TenantStatusService.transition（rehierarchy 片一治理换轴归位：准入态权威上移 tenant.status 真列单点·§9.4 迁移表）；此处只保留行级读与硬删连带（deleted 终态后的运维硬删留接口）。

    destroyTenant

    • destroyTenant(tenantId: string): Promise<{ purgedOrgs: number }>

      租户硬删连带（NFR-6 删除半）：清除该租户名下所有组织（含 1:1 骨架自持租户 id==org.id 那一组）

      • 租户行 + 名下订阅行；各子表由 DB FK cascade 自动消灭。

      Parameters

      • tenantId: string

        目标租户 id。

      Returns Promise<{ purgedOrgs: number }>

      purgedOrgs＝本次连带消灭的组织行数（0 表示租户本体不存在·调用方转 404 幂等）。

      Remarks

      单一卡点·应用层不逐表删；前置闸（仅 tenant.status——准入态归位单点——处 deleted 终态可硬删）在 application 层 handler 裁决， 访问控管在 controller guard——本 port 供纯粹连带消灭动作，不叠业务门槛。事件补删归 handler（需 eventStore）。
