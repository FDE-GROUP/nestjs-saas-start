模块按 Clean Architecture 分层组织：
- `api/`：NestJS Controller + orpc `@Impl` 适配器，仅暴露 `exportMe` / `deleteMe` 两个受 `SessionGuard` 保护的端点，经 `CommandBus` / `QueryBus` 转发到应用层。
- `application/`：CQRS 契约——`commands/` 下 `DeleteUserCommand` + `DeleteUserCommandHandler`；`queries/` 下 `ExportUserDataQuery` + `ExportUserDataQueryHandler`；`read-models/` 定义纯类型返回形状（非物化投影）。
- `domain/repositories/`：声明 `USER_REPOSITORY` token、`UserRecord`、`UserRole`、`UserRepository` 接口，作为依赖倒置的读端口。
- `infrastructure/repositories/`：`MikroUserRepository` 实现该端口，使用 MikroORM `fork()` 取独立 em 做只读查询。
- `users.module.ts` 装配所有 handler、注册 `USER_REPOSITORY` → `MikroUserRepository` 绑定，并 import `CqrsModule`。

依赖方向单向向外：controller → application handlers → domain ports → infrastructure adapters；写侧（删除）不直接碰 ORM，而是通过 `AUTH_USER_STORE`（auth 域端口）执行硬删，再直连 `EVENT_STORE.deleteByAggregate('user', ...)` 补删事件行，遵循“表所有权归属主”的切片 A 规则。
