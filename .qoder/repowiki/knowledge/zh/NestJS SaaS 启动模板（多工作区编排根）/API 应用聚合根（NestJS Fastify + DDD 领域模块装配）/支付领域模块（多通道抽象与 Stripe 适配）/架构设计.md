模块按 DDD 四层划分，依赖方向严格自外向内：
- `api/`：NestJS Controller，使用 `@Impl` + oRPC 契约暴露 test/createCustomer/createCheckout/retrieveCheckout/refund 五个 REST 端点；webhook 保留原始 REST 以直取 `request.rawBody` 做签名校验。
- `application/`：`PaymentService` 作为门面编排层，负责懒解析、金额校验（委托 `Money` VO）、调用策略选择并委托端口。
- `domain/`：纯领域层，零框架依赖——`ports/payment-provider.port.ts` 定义统一 `PaymentProvider` 接口及跨通道归一化引用类型；`policies/provider-selection.policy.ts` 提供纯函数 `selectPaymentProvider`（配置指定 → 回退 stripe）；`value-objects/money.ts` 提供不可变 Money 值对象，采用 result-union 返回构造结果。
- `infrastructure/`：`StripePaymentProvider` 实现端口，封装 Stripe SDK 客户端实例与事件验签，并将 Stripe 原生对象映射为归一化引用。

装配由 `payment.module.ts` 的静态 `register()` 动态完成：根据 `ConfigService.getStripeConfig().secretKey` 决定是否注册 Stripe 提供者，注入到 `'PAYMENT_PROVIDERS'` token；未配置时 `PaymentService.resolve()` 抛 `ServiceUnavailableException`（NFR-2 未配即降级）。模块自身标记 `@Global()` 并通过 `exports: [PaymentService]` 对外暴露。
