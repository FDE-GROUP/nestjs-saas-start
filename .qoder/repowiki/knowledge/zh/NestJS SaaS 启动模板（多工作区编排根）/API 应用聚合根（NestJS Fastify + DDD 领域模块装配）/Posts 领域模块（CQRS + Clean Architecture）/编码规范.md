- 领域实体采用不可变设计：私有构造函数 + 静态工厂 `draft`/`restore`，状态变更通过返回新实例的纯方法（如 `withPublished`）实现，而非原地修改。
- 仓储实现通过 `MikroOrmService.fork()` 获取独立 EntityManager，避免共享全局 em，并在所有读写路径先经 `TenantIsolationService.requireActiveTenantId()` 做 fail-closed 租户校验。
- CQRS 用例以独立的 Command/Query 类（继承 `BaseCommand`/`BaseQuery`）承载意图，handler 仅负责编排，不直接访问数据库或领域实体。
- API 控制器使用 `@Impl(singleContract)` 单契约模式，配合 `os.input().output().meta().handler()` 链式 DSL 完成参数校验、响应 schema 与 openapi meta 的统一声明。
- 跨层数据传输统一经由 `application/read-models` 中的只读投影类型（如 `PostReadModel`），领域实体从不直接泄漏到 api 层。
- 租户/组织/workspace 作用域在仓储层集中解析（`scope()`/`readScope()`），应用层与领域层不感知具体租户标识，由仓储适配器作为隔离唯一卡点。
