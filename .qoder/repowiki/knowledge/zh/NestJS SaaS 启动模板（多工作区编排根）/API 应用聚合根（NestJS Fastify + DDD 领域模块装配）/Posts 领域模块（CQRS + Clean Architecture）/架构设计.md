模块按 Clean Architecture 四层自内向外组织：
- `domain/`：纯业务层，`entities/post.ts` 定义不可变充血实体 `Post`（两阶段构造 `draft`/`restore`、`withPublished`/`withUnpublished` 纯转移），`repositories/post.repository.ts` 仅声明端口接口。
- `application/`：用例编排层，`commands/` 与 `queries/` 分别定义 `CreatePostCommand` / `ListPostsQuery` 及其 handler，依赖 `read-models/post.read-model.ts` 作为跨层投影契约；通过 `@nestjs/cqrs` 的 CommandBus/QueryBus 调度。
- `infrastructure/`：MikroORM 适配层，`entities/post.entity.ts` 为物理 ORM 实体，`repositories/mikro-post.repository.ts` 实现 domain 端口，负责租户/组织/workspace 作用域注入、UUIDv7 游标分页、`em.fork()` 隔离执行及 entity↔domain 映射（`post-mapping.ts`）。
- `api/`：传输层，`posts.controller.ts` 使用 `@orpc/nest` 的 `@Impl(contract)` 装饰器将每个方法绑定到 `@saas/api-contract` 中的单一 ProcedureContract，并通过 `os.input/output.meta.handler` 链完成 zod 校验、openapi meta 与 CQRS 调用；类级 `TenantIsolationGuard` 保证 fail-closed 租户隔离。
- `posts.module.ts` 是 Nest 装配入口，注册 CQRS handlers 并以 `{ provide: POST_REPOSITORY, useClass: MikroPostRepository }` 将 domain 端口绑定到唯一基础设施实现，体现依赖倒置。
依赖方向严格单向：api → application → domain ← infrastructure，domain 零框架依赖。
