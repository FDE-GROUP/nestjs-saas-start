模块按 DDD 分层组织：
- `domain/policies`：纯函数策略（`rbac.policy.ts`）定义自定义角色 key 词法白名单与 grant conditions 形状闸（仅等值/$in），零 IO，作为写前 fail-closed 闸门。
- `domain/repositories` + `domain/ports`：声明 `TenantRbacRepository` 端口及 `RoleAssignabilityReader` / `TenantInvitationManager` / `TenantMembershipManager` 等跨上下文 published port，以 Symbol token 暴露；领域结果码用字面量 union（不抛异常）。
- `application`：`TenantRbacAdminService` 是管理门面应用服务，从 `TenantIsolationService` 取活动租户与 actor，委派仓储并转译领域结果为 HTTP 异常，每次写后调用 `PermissionInvalidator.invalidate(tenantId)` 失效进程内缓存。
- `infrastructure`：MikroORM 实体（`entities/rbac.entities.ts`）+ 仓储适配器（`mikro-organization-rbac.repository.ts` 等）实现 domain 端口；`casl-permission.checker.ts` 实现 `PermissionChecker` 与 `PermissionInvalidator`，基于 `@casl/ability` 的 `createMongoAbility` 将 grant 行投影为 `CaslScopedAbility`，维护 per-(tenant,key) 的 Map 缓存（LRU 上限 2048），支持守卫路径类型级判定与 check 级实例判定（解析 `{{userId}}` 模板）。
- `api`：`AuthorizationAdminController` 暴露 `tenants/roles` 路由，`AuthorizationGuard` 由 core 提供并在本模块注册。
- `authorization.module.ts` 以 `@Global()` 导出 Guard、checker/invalidator 端口、repository 与三个 manager port，供其他限界上下文消费；依赖方向单向：infrastructure → domain ← application ← api，core 通过 symbol token 反向注入。
