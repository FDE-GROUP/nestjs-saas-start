模块按 NestJS feature 标准切分为两层：
- `api/`：NestJS 装配层。`mcp.module.ts` 注册两个 controller（`McpController` 暴露 `/mcp` POST/DELETE，`McpCredentialsController` 管理凭证明文）和四个 provider；通过 `{ provide: MCP_TOKEN_VERIFIER, useClass: McpTokenVerifierService }` 把本模块的 verifier 实现注入到 auth 属主上下文的 token 解析管线，并 export `MCP_TOKEN_VERIFIER` 供外部消费。
- `application/`：无框架依赖的业务服务。`McpAgentSurfaceService` 是消费面会话网关——Fastify `reply.hijack()` 后直交 `@modelcontextprotocol/sdk` 的 `StreamableHTTPServerTransport`，进程内 Map 维护带 LRU 逐出与闲置 TTL 清理的会话表，每请求重走 `MCP_TOKEN_VERIFIER.verify → TENANT_SCOPE_RESOLVER.resolveTenantRole → TenantIsolationService.run(ALS)` 鉴权链，再按凭证 scopes 经 `selectToolNames` 动态注册 `McpServer` 工具。
- 依赖方向单向向外：仅通过端口 `MCP_ACCESS_TOKEN_STORE` / `MCP_TOKEN_VERIFIER` 访问 auth 属主上下文，不直接 import entity/em；租户隔离能力来自 `@core/saas-kit`。
- 工具契约集中在 `mcp-tool-registry.ts` 静态表（deny-by-default：空 scope 集 = 零工具），handler 委托 `McpToolExecutorService`。
