模块以 `platform.module.ts` 为 NestJS `@Global()` 装配点，向外暴露 `PlatformOperatorGuard`、`PlatformAuditService` 以及两个端口 `PLATFORM_IDENTITY_LOOKUP`、`PLATFORM_SETTINGS`，供 tenants 等其他模块注入审计与身份判定。

- `api/`：HTTP 控制器切片，`PlatformTenantsController`（9 路由）与 `PlatformUsersController`（3 路由）均使用 `@TenantIsolationExempt()` + `@UseGuards(PlatformOperatorGuard)`，明确声明不绑定租户作用域；每个方法通过 `os.input().output().meta().handler()` 链式注册，内部经 `CommandBus`/`QueryBus` 调用 `@app/modules/organizations/application/*` 中的命令与查询，自身不持有任何表或业务逻辑。
- `infrastructure/`：实现 core 的端口契约——`ConfigPlatformSettings` 适配 `PlatformSettings`（读取 `operatorEmail`），`MikroPlatformIdentityLookup` 通过 MikroORM `fork()` 独立 EM 查询 Better Auth 的 `User.email` 完成 FR-13 经营者判定。
- 依赖方向单向：controller → CQRS Bus → organizations application layer；本模块仅消费 `@core/saas-kit/platform/*` 端口，不反向依赖 tenants 领域实体，避免治理门面吞掉核心域。
- 测试文件（`platform-audit.service.test.ts`、`platform-operator.guard.test.ts`、`platform-tenants.governance.e2e.test.ts`）与模块并列放置，覆盖审计单点、operator guard 与租户治理端到端路径。
