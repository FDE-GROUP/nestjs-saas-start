模块按 `api` / `infrastructure` 两层组织：
- `api/workspaces.controller.ts` 是 NestJS `@Controller('')` 入口，通过 `CommandBus` / `QueryBus` 把请求委派给 `@core/saas-kit` 中的 application 层 Command/Query Handler；路由级守卫 `TenantIsolationGuard` + `AuthorizationGuard` 配合方法级 `@Can` 完成租户与 RBAC 校验，并使用 `@orpc/nest` 的 `@Impl` 将每条路由绑定到 `@saas/api-contract` 的 ProcedureContract。
- `infrastructure/repositories/mikro-workspace.repository.ts` 实现领域端口 `WorkspaceRepository`（来自 `@core/saas-kit/modules/workspaces/domain/repositories/workspace.repository`），以 `MikroOrmService.fork()` 获取独立 EntityManager，所有读写强制注入 `tenantId` 与 `organizationId` 谓词，作为跨租户泄漏的唯一卡点。
- `infrastructure/entities/workspace.entity.ts` 通过 `buildRuntimeEntity` 从 `WORKSPACE_META` 同时生成迁移实体与运行时 EntitySchema，是 `workspace` 表列定义的唯一真相源。
- `workspaces.module.ts` 使用依赖倒置将 `WORKSPACE_REPOSITORY` token 绑定到 `MikroWorkspaceRepository`，并注册 CQRS handler。
- `api/response/workspace.response.ts` 提供 Swagger DTO，并通过编译期双向赋值断言与领域 `WorkspaceReadModel` / `@saas/contracts` 输出类型保持结构恒等。
依赖方向单向向外：本模块消费 `@core/saas-kit` 的领域、应用、授权、租户隔离能力，不反向依赖它们。
