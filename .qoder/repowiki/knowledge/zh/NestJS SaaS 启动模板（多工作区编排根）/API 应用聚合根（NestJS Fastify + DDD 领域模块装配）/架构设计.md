根 `AppModule` 是唯一的装配点：先注册 `ORPCModule.forRoot`（提供 `ImplementInterceptor`、全局错误编码器 `restErrorResponseBodyEncoder` 与状态映射 `restErrorStatusMap`），再依次导入 `ConfigModule → RateLimitModule → LoggerModule → DatabaseModule → MikroOrmModule → AppI18nModule → CommonModule → HealthModule → AuthModule.forRoot()`；随后以固定顺序注入 `AuthorizationModule`、`PlatformModule`、`TenantIsolationModule`，保证 APP_GUARD 执行序为「限流(最廉价拒绝) → 会话墙 401 → 租户墙 403」。

- 共享层（common/config/database/i18n/logger/mailer）通过 `@Global` 或根模块单例向所有领域模块暴露横切能力。
- 领域模块（auth/authorization/organizations/payment/platform/posts/storage/subscriptions/users/workspaces）各自持有 `api/application/domain/infrastructure` 四层结构，仅通过端口（ports/repositories）跨域调用，不直接依赖其他领域。
- 叠加层（features/mcp、odoo-provisioning、odoo-rpc-api）由 `feature-loader.ts` 运行期探测装配，末尾展开到 `FEATURE_MODULES`，避免主应用被具体叠加层绑架。
- 多租户隔离由 `tenant-isolation` 模块在请求级注入租户上下文，并配合 `database/tenant-isolation-filter` 对 MikroORM 查询施加 tenant 过滤。
