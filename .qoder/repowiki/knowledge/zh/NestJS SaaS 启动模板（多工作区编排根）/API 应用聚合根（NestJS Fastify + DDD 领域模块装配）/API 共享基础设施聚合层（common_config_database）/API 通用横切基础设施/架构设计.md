模块以 `common.module.ts` 作为全局装配入口（`@Global()`），集中注册跨应用的 `APP_FILTER`（`HttpExceptionFilter` + `StandardSchemaValidationExceptionFilter`）、`APP_INTERCEPTOR`（`LoggingInterceptor` → `TransformInterceptor` → `StandardSchemaSerializerInterceptor`）以及 `APP_GUARD`（在 `rate-limit.module.ts` 中注入 `ThrottlerGuard`）。内部按职责分目录：
- `filters/`：HTTP 异常到统一 `ErrorResponse` 信封的兜底渲染，以及 Standard Schema 校验异常的专用过滤。
- `interceptors/`：结构化请求日志与响应体转换。
- `errors/`：错误信封字段单源与 Standard Schema 校验异常类型。
- `contracts/`：对外暴露的 `ErrorResponse` 契约及契约一致性测试。
- `orpc/`：oRPC 的 `oc`/`os` 根，预挂 `restErrorMiddleware` 把 handler 抛出的 `HttpException` 转成 REST 错误信封。
- `health/`：Nest 模块形式的 `/health` 控制器。
- 顶层文件：`fastify-http-options.ts` 构造 Fastify 实例选项（pino 日志、`trustProxy`、关闭重复日志）、`request-id.hook.ts` 在 Fastify `onRequest` 阶段注入 `x-request-id` 并写入 ALS 上下文、`validation-pipe.ts` 是全局 `StandardSchemaValidationPipe` 的单源工厂、`trusted-proxies.ts` 解析代理白名单、`rate-limit.module.ts` 通过 `RATE_LIMIT_DEFAULT` 常量暴露全局限流策略。
依赖方向单向向外：本模块依赖 `@app/logger`、`@core/saas-kit`、`@nestjs/*`、`@orpc/*`、`@saas/contracts`，不被业务模块反向引用；业务侧通过 `imports: [CommonModule, RateLimitModule]` 或从 `./common/orpc` 导入 `os`/`oc` 使用能力。
