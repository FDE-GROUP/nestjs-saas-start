模块以 `database/eventing/` 为根，围绕 `event` 表实现 ES Phase B 后半的完整链路：
- 持久层：`entities/event.entity.ts` 定义 `EVENT_META` + `Event` 运行时实体（含 `dispatchedAt/attemptCount/lastError` outbox 列及 `event_aggregate_version_key`、`event_event_id_key` 唯一约束），由 `MikroEventStore` 实现 `@core/saas-kit/shared-kernel/domain/event-store.port.EventStore` 端口，提供 append/load/deleteByAggregate，并发通过 DB 唯一键 fail-loud。
- 发布路由：`domain-event-publisher.ts` 的 `DefaultDomainEventPublisher` 根据 `EVENT_PUBLISH_MODE` 在 inproc/shadow/outbox 三模间切换；outbox 模式借助 `TransactionScope`（AsyncLocalStorage 持有活跃事务 em）强制要求调用方在 UoW 内发布，否则抛错。
- 事务边界：`mikro-unit-of-work.ts` 暴露 `MikroUnitOfWork.run`，外层复用 ALS 中事务 em、外层无事务时创建新事务并注入 ALS，使域写与事件 append 同生共死。
- 投递中继：`outbox-relay.ts` 的 `OutboxRelay` 是后台轮询器（`setInterval`），按 `BATCH_SIZE=50` 用 `FOR UPDATE SKIP LOCKED` 拉取未投递行，在事务内 claim（置 `dispatchedAt`）+ 经 `EVENT_TYPE_REGISTRY` 重建 DomainEvent 实例，提交后尽力 `publishAll` 至 `@nestjs/cqrs` EventBus，保证「不提交则不投递」消灭幻影事件。
- 类型还原：`event-type-registry.ts` 集中维护 eventType→类映射，`event-hydration.ts` 抽单源 `hydrateEventRow` 供 store.load 与 bootstrap 脚本共用，未知 eventType fail-loud。
依赖方向单向向外：本模块消费 `@core/saas-kit/shared-kernel/domain/*` 端口与 `@nestjs/cqrs`、`@mikro-orm/core`，被上层 `MikroOrmModule` 装配导出。
