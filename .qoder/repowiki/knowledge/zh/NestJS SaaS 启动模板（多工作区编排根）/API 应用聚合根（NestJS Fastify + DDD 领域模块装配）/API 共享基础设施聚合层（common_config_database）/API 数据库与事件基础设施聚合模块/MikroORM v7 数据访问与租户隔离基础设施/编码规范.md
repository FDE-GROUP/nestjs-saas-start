- ORM 初始化拆为两个工厂：`initMikroOrm`（运行时无 extensions）与 `initMigrationOrm`（带 Migrator extension），分别注册不同的 entities 集合，保持运行期与迁移期完全解耦。
- 实体定义采用双形派生：业务表通过 `column-meta.ts` 的 `TableMeta` 单源同时产出 `buildMigrationEntity`（FK 关系）与 `buildRuntimeEntity`（扁平 string 列），避免 DDL 与运行时描述漂移。
- 所有实体统一使用 `EntityCaseNamingStrategy`，物理列名即 camelCase 原属性名，使手写 SQL 与 ORM 输出键名一致，无需 snake↔camel 转换。
- EntityManager 获取一律经 `MikroOrmService.fork()` 或 `newTransactionEm()`，禁止直接共享全局 `orm.em`，每个请求/操作持独立 em 实例。
- 租户隔离通过全局 filter `tenantIsolation` 强制生效（`default:true`），仓储层仍保留显式 `{tenantId}` where 谓词作为纪律兜底，形成机制+纪律双保险。
- 跨租/治理/seed/迁移等无 ALS 租户上下文的读写通过传空参数或 `scoped:false` 绕过过滤，filter cond 在无 tenantId 时返回恒真谓词，不改变既有行为。
