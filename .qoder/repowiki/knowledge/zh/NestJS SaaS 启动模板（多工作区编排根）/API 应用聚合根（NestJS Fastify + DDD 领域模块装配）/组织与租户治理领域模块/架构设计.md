模块按 NestJS 分层 + CQRS 组织：
- `api/`：NestJS Controller（`OrganizationsController` / `OrganizationsOrgAdminController` / `OrganizationsSelfController` / `TenantsController`），仅做鉴权守卫（`SessionGuard`、`PlatformOperatorGuard`）、参数校验（`@saas/api-contract` + `@orpc/nest` 的 `Impl`/`os.input().output()`）和命令派发，不承载业务。
- `application/`：CQRS 层。`commands/` 下每个用例一个 Command DTO + Handler（如 `ApproveOrganizationCommandHandler`），统一委托共享策略函数 `governed-organization-transition.ts` 驱动状态迁移；`queries/` 下为只读查询处理器；`read-models/` 定义面向应用层的扁平 DTO；`tenant-member-facade.service.ts` 作为租级成员/邀请门面，组合 `TENANT_MEMBERSHIP_MANAGER` / `TENANT_INVITATION_MANAGER` / `ROLE_ASSIGNABILITY_READER` / `QuotaService` 并桥接 BA 遗留 `BA_MEMBER_DIRECTORY_WRITER`。
- `domain/repositories/`：纯接口 + symbol token（`ORGANIZATION_GOVERNANCE_REPOSITORY`、`ORGANIZATION_PROVISIONING_REPOSITORY`、`USER_GOVERNANCE_REPOSITORY`、`TENANT_DIRECTORY_REPOSITORY`、`BA_MEMBER_DIRECTORY_WRITER`），定义跨租户治理、Odoo 绑定、用户治理、租户目录等端口契约。
- `infrastructure/`：MikroORM 适配层，含 `entities/`（`ba-org.entities.ts`、`tenant.entity.ts`、`audit-log.entity.ts`）与 `repositories/mikro-*.repository.ts` 实现，所有 EM 通过 `mikro.fork({ scoped: false })` 绕过 ALS 租户过滤以支持平台级全量访问。
- `lifecycle/`：仅放测试文件，真实 `TenantStatusService` / `UserStatusService` 及其 store 由 `@core/saas-kit/modules/organizations/lifecycle` 提供，本模块在 `organizations.module.ts` 中以 `{ provide: TENANT_STATUS_STORE, useClass: MikroTenantStatusStore }` 形式装配。
- `organizations.module.ts` 标记 `@Global()`，导出 `TenantStatusService`、`UserStatusService`、`AUDIT_LOG_STORE`、`ORGANIZATION_ODOO_BINDING_*` 等跨上下文消费面；依赖方向单向：api → application → domain ports → infrastructure，且通过 `useExisting` 将同一 `MikroOrganizationGovernanceRepository` 同时注册为 reader/writer 端口以复用实例。
