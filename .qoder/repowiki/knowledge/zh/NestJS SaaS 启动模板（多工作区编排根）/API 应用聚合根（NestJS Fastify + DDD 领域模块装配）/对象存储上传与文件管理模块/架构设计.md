模块严格遵循 Clean Architecture 分层：
- `api/`：NestJS 控制器层，upload 走 Fastify multipart REST 路由，delete/getFileUrl 通过 oRPC `@Impl` + `storageDeleteContract/storageUrlContract` 暴露；DTO 与 Swagger 响应定义在 `dto/`、`response/`。
- `application/`：`StorageService` 作为门面编排层，仅做策略调用与 HTTP 异常映射，不碰 IO。
- `domain/`：纯领域层，零框架依赖——`ports/storage-provider.port.ts` 定义 `StorageProvider` 出站接口（upload/delete/getFileUrl），`policies/` 内 `provider-selection.policy`（按配置选 provider 并回退 s3）和 `upload.policy`（尺寸/MIME 校验 result-union）为纯函数，`value-objects/storage-key.ts` 封装 key 生成规则。
- `infrastructure/`：具体实现，`BaseStorageProvider` 抽取三通道共享逻辑（临时文件落盘→流式上传→清理、ETag 归一、URL 拼接），`S3StorageProvider` / `AliOssStorageProvider` / `TencentCosStorageProvider` 各自实现 SDK 调用。

装配边界在 `storage.module.ts`：通过静态 `register()` 动态注册 `STORAGE_PROVIDERS` 令牌，根据 `ConfigService.getStorageConfig().provider` 注入 s3/alioss/tencentoss 实例，默认始终包含 s3 作为回退。依赖方向单向：api → application → domain ← infrastructure，domain 不反向依赖任何上层。
