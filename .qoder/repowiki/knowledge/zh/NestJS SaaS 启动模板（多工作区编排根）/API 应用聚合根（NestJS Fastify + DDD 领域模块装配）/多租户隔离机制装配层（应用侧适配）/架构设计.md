模块以 `TenantIsolationModule`（`@Global()` + `NestModule`）为唯一入口：通过 `configure(consumer)` 将 `TenantIsolationMiddleware` 注册到 `*` 路由，借助 AsyncLocalStorage 在请求生命周期内绑定活动租户；同时把 `TenantIsolationGuard` 作为 `APP_GUARD` 全局注册实现 deny-by-default 的租户墙。

内部按「core 端口 / 应用侧适配」两层划分：
- `infrastructure/auth-session.reader.ts` 实现 `RequestSessionReader` 端口，封装对 Better Auth 实例 (`AuthInstanceInjectKey`) 的调用，并内置廉价短路（无 cookie / auth 表面路径 / bypass 路径）与段对齐路径匹配 `pathSegmentMatch`。
- `infrastructure/mikro-tenant-scope.resolver.ts` 实现 `TenantScopeResolver` 端口，基于 `MikroOrmService.fork()` 纯读 `Organization.tenantId`、`Tenant.orgVisibility`、`TenantRoleAssignment.roleKey`、`TenantMembership`，并在自身是隔离机制锚时显式使用 `fork({ scoped: false })` 绕过当前 ALS 过滤。

依赖方向单向向外：本模块仅消费 `@core/saas-kit/tenant-isolation` 暴露的端口 token（`SESSION_READER`、`TENANT_SCOPE_RESOLVER`），由本模块在 DI 容器中以 `useClass` 绑定具体实现；领域策略（deny-list、配额、RBAC 裁决）已迁出至 `OrganizationsModule`/`SubscriptionsModule`/`AuthorizationModule`，本模块只保留机制骨架。测试覆盖 guard、middleware、DI 上下文、E2E 隔离场景及矩阵用例。
