模块遵循 DDD + CQRS 分层：
- `domain/repositories/workspace.repository.ts` 定义纯 TypeScript 接口 `WorkspaceRepository`、`WorkspaceDraft`、`WorkspaceRecord` 以及 DI token `WORKSPACE_REPOSITORY`，作为领域自有的仓储端口；所有写操作由仓储适配层从可信上下文注入 `organizationId`，调用方不得携带租户参数，以此作为 FR-5 租户隔离的唯一卡点。
- `application/commands` 与 `application/queries` 分别承载写侧命令（`CreateWorkspaceCommand` / `DeleteWorkspaceCommand` / `UpdateWorkspaceCommand`）与读侧查询（`ListWorkspacesQuery`），均继承 shared-kernel 的 `BaseCommand` / `BaseQuery`。
- `application/commands/handlers` 与 `application/queries/handlers` 通过 `@nestjs/cqrs` 的 `@CommandHandler` / `@QueryHandler` 装饰器注册处理器；写侧 handler 从 `TenantIsolationService` 取 `userId` 盖章 `ownerId`，读侧 handler 经 `PERMISSION_CHECKER.listPredicate` 下推实例级授权谓词（`all`/`where`/`none`）再调用仓储端口。
- `application/read-models/workspace.read-model.ts` 暴露 `WorkspaceReadModel`，当前与 `WorkspaceRecord` 同形但保持类型边界以便未来读写模型解耦。
- 依赖方向单向：handlers → domain repository port → 外部适配器；handler 同时依赖 `TenantIsolationService` 与 `PermissionChecker` 两个共享内核端口。
