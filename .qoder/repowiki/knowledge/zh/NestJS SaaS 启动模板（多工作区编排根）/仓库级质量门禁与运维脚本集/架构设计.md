脚本按职责分为三类：
- 编排入口：`ci.ts` 通过 `node:child_process.spawnSync('pnpm', ...)` 顺序触发 lint → type-escape ratchet → domain-layout → feature-isolation → stories-drift → i18n-key-parity → overturned-rulings → config-contract → (full 模式) build + web/odoo-rpc-web typecheck + test-types + orpc-contract + tenant-scoped-registry → vitest，并附带 advisory-only 的 `fallow:arch` 边界检查；`ci-fullstack.ts`、`e2e-web.ts` 是扩展编排。
- 恒等闸（verify-*）：纯文本/目录扫描型工具，如 `verify-domain-layout.ts`（校验 `apps/api/*/domain` 下文件落入 7 个 canonical 子目录）、`verify-type-escape-ratchet.ts`（对比 `scripts/type-escape-baseline.json` 基线，只拦新增逃逸）、`verify-i18n-key-parity.ts`、`verify-overturned-rulings.ts`、`verify-config-contract.ts`、`verify-tenant-scoped-registry.ts`、`verify-stories-drift.ts`、`verify-feature-isolation.ts`、`verify-compose-contract.ts`、`verify-prod-boot.ts`。
- Doctor / 运维 CLI：`mikro-migrate.ts`、`mikro-migration-create.ts`、`es-bootstrap-subscriptions.ts`、`member-count-doctor.ts`、`odoo-binding-doctor.ts`、`odoo-binding-drift.ts`。

依赖方向单向向外：脚本通过相对路径直接 import 仓库源码（如 `../apps/api/src/load-env.ts`、`@core/saas-kit/...`），不被业务代码反向引用；`tsconfig.json` 仅对 `*.test.ts` 开启编译（`noEmit`），其余脚本由 `tsx`/Node ESM 直接执行。测试文件与实现文件同目录配对（如 `odoo-binding-drift.test.ts` 对应 `odoo-binding-drift.ts`）。
