仓库采用三层协作：apps/* 为消费端（api/web/odoo-rpc-web），libs/* 为框架无关内核（core/saas-kit、contracts、ba-mikro-adapter），packages/* 为发布产物（@saas/api-client）。跨子模块的耦合点集中在：
- 依赖契约：api 通过 @orpc + zod 暴露 procedure，web 与 api_client_package 通过 @saas/api-contract 派生 typed client，三方由 libs/contracts 中的 zod schema 保证一致。
- 运行时装配：apps/api 的 AppModule 在启动时加载 core_lib 的租户/授权/领域模块，并挂载 Better Auth × MikroORM v7 适配器；shared_libs 的 ba-mikro-adapter 同时被 api 与 core 使用。
- 构建链：根 package.json 的 build 顺序为 build:libs → build:client → build:nest，确保 libs 先产出声明，api-client 再基于 contracts 生成客户端，最后编译 Nest 应用。
- 测试与质量：vitest.config.ts 用 unplugin-swc 支持装饰器元数据，统一扫描 apps/libs/packages/scripts 下的 *.test.*；scripts_tooling 提供 domain/layout/i18n/type-escape/stories 等架构恒等闸，作为 pnpm ci / verify:* 命令入口。
- 部署：docker_infra 提供 all-in-one Odoo+SaaS 镜像与 OpenAPI 3.1 契约导出，供演示与文档生成共用。
