模块遵循 NestJS feature 专属区条 `{api, application, infrastructure}` 三层划分，由 `odoo-rpc-api.module.ts` 作为装配根注册控制器、服务与基础设施 provider。
- api 层：`OdooRpcController` 暴露 GET `/api/v1/odoo/{partners,products}`，使用 `@orpc/nest` 的 `@Impl` + `openapi` 元数据声明契约，委托给应用层；契约定义集中在 `odoo-rpc.schemas.ts`（zod schema），供前端经 vite alias 直接引用，避免进入 `@saas/contracts`。
- application 层：`OdooReadService` 实现业务用例，硬编码模型/域/字段白名单（反透传红线），通过 `TenantIsolationService` 取活动租户 → `OrganizationOdooBindingReader` 解析公司绑定 → `canUseOdoo` 裁决 ready 状态，再调用基础设施层；所有上游行经 zod `parse` 校验，模式漂移即 502。
- infrastructure 层：`OdooJsonClient` 基于原生 `fetch` 直连 Odoo `/jsonrpc`，封装 `authenticate` + `execute_kw`，并提供 `searchRead` / `searchCount` 便捷方法；凭据来自 `ConfigService` 的 `ODOO_DB` / `ODOO_API_KEY` / `ODOO_LOGIN` / `ODOO_BASE_URL`，缺任一键即 503 fail-closed。
依赖方向单向向下（api → application → infrastructure），不反向依赖；鉴权与租户隔离由全局 guard 与 `TenantIsolationService` 承担，本 feature 零耦合 auth 上下文。
