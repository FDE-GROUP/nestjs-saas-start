- 外部通道通过 `domain/ports` 中的纯 TypeScript 接口抽象，基础设施实现位于 `infrastructure/` 并按 `id` 注册到 `PAYMENT_PROVIDERS` token，由 `PaymentModule.register()` 依配置条件装配。
- 领域不变量通过 value-object 类 + static factory 返回 result-union（如 `Money.fromMinorUnits` 返回 `{ok, money}` | `{ok:false, reason}`），失败不抛异常而返回拒绝原因联合。
- HTTP 控制器方法统一使用 `os.input(...).output(...).meta(...).handler(...)` 链式 oRPC 风格，契约与 zod schema 分别来自 `@saas/api-contract` 与 `@saas/contracts` 两个单源包。
- Webhook 等需要原始请求体的入口保留传统 NestJS `@Post` + `RawBodyRequest` 写法，不走 `@Impl` 以规避 rawBody 在 oRPC 管线中的丢失风险。
- 未配置的支付通道在运行时而非启动期报错：`PaymentService.resolve()` 懒解析并在首次调用时抛出带 `ERROR_CODES.BILLING_PROVIDER_NOT_CONFIGURED` 的 `ServiceUnavailableException`。
