本模块由三个文件构成应用启动链：
- `load-env.ts` 作为副作用模块被 `main.ts` 首行 import，利用 Node ESM 静态提升保证在 `config/envs/*.ts` 顶层求值前完成 `dotenv.config()`，从而消除 node/bun 运行时差异。
- `main.ts` 是进程入口，负责创建 FastifyAdapter（透传 `AUTH_TRUSTED_PROXIES`）、读取 `ConfigService` 中的 app/swagger/cors/storage 配置、执行数据驻留合规检查（`assertDataResidency` + `resolveEnforceMode`，strict 模式下违规直接 `process.exit(1)`），并依次挂载全局校验管道、request-id hook、compression/helmet/CORS/multipart 等 Fastify 插件，最后按 `swaggerConfig.enabled` 条件启用 Swagger/OpenAPI YAML 端点并监听端口。
- `app.module.ts` 是 Nest 根模块，按严格导入序组织依赖：ORPCModule → ConfigModule → RateLimitModule（最廉价拒绝）→ LoggerModule → DatabaseModule/MikroOrmModule → AppI18nModule → CommonModule → HealthModule → AuthModule.forRoot() → AuthorizationModule → PlatformModule → TenantIsolationModule → 各业务 Module → MailerModule → 尾部展开 `FEATURE_MODULES`；注释明确标注了守卫执行顺序与 feature-loader 的探测装配机制。
依赖方向单向向外：bootstrap 层消费 `config`、`common`、`modules/*`、`features`，不被其反向引用。
