模块按职责分为三层：
- 运行时装配层：`mikro-orm.module.ts` 以 `@Global()` 暴露 `MikroOrmService`、`TransactionScope`（ALS 事务）和 `UNIT_OF_WORK` 端口实现；`mikro-orm.service.ts` 是懒建连接持有者，首次 fork 时才调用工厂建连，每次读写通过 `orm.em.fork()` 取独立 EntityManager，避免 V4 时代的全局 em 串租户问题。
- ORM 初始化层：`mikro-orm.factory.ts` 是无状态工厂，解析 `DATABASE_URL` 并注入 `EntityCaseNamingStrategy`（camelCase 物理列）与 `allowGlobalContext: true`；`sys-entities.ts` 聚合 BA 七表 + Post + 元数据四表 + RBAC + AuditLog + MCP 凭证作为 `MIKRO_SYS_ENTITIES`。
- 迁移专用层：`migration/mikro-migration.config.ts` 单独 init 一个带 `Migrator` extension 的 ORM，仅被离线脚本使用，与运行时无耦合；`migration/migration-entities.ts` 用 `defineEntity` 逐列忠实复刻生产 DDL，并通过 `column-meta.ts` 的 `buildMigrationEntity` / `buildRuntimeEntity` 从同一份 `TableMeta` 派生两套实体（迁移端 FK 走 `manyToOne.mapToPk()`，运行时端 FK 走扁平 `p.string()`），保证 DDL 恒等。
- 租户隔离机制：`tenant-isolation-filter.ts` 注册全局 filter `tenantIsolation`，默认生效，从 `tenantIsolationStorage` ALS 作用域派生 `tenantId`/`organizationId`/`orgIsolated`，对 org-partitioned 实体在 isolated+无活动 org 时返回哨兵值拒所有（fail-closed），跨租/治理/seed 等无上下文场景恒真不筛（fail-open 豁免）。
