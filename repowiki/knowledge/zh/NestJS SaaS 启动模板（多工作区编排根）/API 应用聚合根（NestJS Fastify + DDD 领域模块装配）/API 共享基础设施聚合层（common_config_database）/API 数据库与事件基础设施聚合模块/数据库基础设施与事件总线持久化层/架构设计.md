模块按职责分为三层：
- `mikro/`：MikroORM 运行时底座。`mikro-orm.factory.ts` 负责 `initMikroOrm`；`mikro-orm.service.ts` 持有懒建 `MikroORM` 实例，每次读写经 `fork()` 取独立 `EntityManager`（禁全局 `orm.em`），并在活跃 UoW 事务内返回事务 em；`tenant-isolation-filter.ts` 通过 MikroORM v7 动态 filter + ALS 派生参数实现跨租/组织行级隔离，`scoped:false` 显式绕过。
- `eventing/`：事件总线持久化面。`domain-event-publisher.ts` 实现 `DOMAIN_EVENT_PUBLISHER` 端口；`mikro-event-store.ts` 实现 `EVENT_STORE` 端口，以影子追加语义写 `Event` 实体，支持乐观锁 `expectedVersion` 与流回放；`outbox-relay.ts` 在 `EVENT_PUBLISH_MODE=outbox` 时定时轮询 event 表，用 `FOR UPDATE SKIP LOCKED` claim + 提交后 `publishAll` 保证「不提交则不投递」的甲档语义；`transaction-scope.ts` 基于原生 `AsyncLocalStorage` 承载活跃事务 em，使发布点关键段内的仓储写与事件 append 复用同一事务。
- 顶层装配：`database.module.ts` 是 `@Global()` 模块，将 `MikroEventStore` 绑定到 `EVENT_STORE`、`DefaultDomainEventPublisher` 绑定到 `DOMAIN_EVENT_PUBLISHER` 并 export，供各上下文就地解析；`table-ownership.guard.ts` / `entity-column-law.ts` 提供表所有权守卫与列约束校验。
依赖方向单向：eventing → mikro；database.module 聚合两者并向外暴露契约，避免上层直接耦合 ORM。
