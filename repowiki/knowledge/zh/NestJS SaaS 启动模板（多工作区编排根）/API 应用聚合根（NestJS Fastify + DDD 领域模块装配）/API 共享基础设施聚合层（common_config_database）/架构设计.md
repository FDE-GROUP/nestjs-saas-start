三个子模块通过 `app.module.ts` 按固定顺序装配：ConfigModule 最先启动以解析环境变量并触发数据驻留守卫；DatabaseModule + MikroOrmModule 随后建立连接、租户隔离过滤与领域事件存储；CommonModule/HealthModule/RateLimitModule 最后挂载过滤器、拦截器、校验管道、oRPC 错误序列化与健康检查。三者之间不存在直接 import 依赖，而是通过 Nest DI 契约解耦：config 暴露 typed ConfigService，database 暴露 EVENT_STORE/DOMAIN_EVENT_PUBLISHER，common 暴露全局过滤器与 oRPC 上下文工厂；业务模块仅消费这些契约，不感知实现细节。
