模块以 NestJS `@Global()` 的 `ConfigModule` 为入口，通过 `NestConfigModule.forRoot` 注入 `.env` 并顺序 `load` 默认配置与环境特定覆盖（`default.ts` → `development.ts` / `production.ts`），运行时由 `NODE_ENV` 决定加载哪份环境文件。

- 分层结构：`config.module.ts` 负责 Nest DI 装配；`config.service.ts` 暴露 typed getter（`getAppConfig/getDatabaseConfig/getStorageConfig/...`）作为业务消费面；`interfaces/config.interface.ts` 定义 `Config` 及其子域类型契约；`data-residency.ts` 是纯函数模块，独立于 Nest DI，用于启动期校验数据库 host 与存储 region 是否位于中国大陆白名单。
- 校验双轨：Zod schema 在 `createSchemaForEnv` 中集中声明（`baseSchema` + `betterAuthSchema`），由 `@nestjs/config` v12 的 `validationSchema` 一等公民消费，替代旧 Joi；字段级解析器（`parseCorsOrigins`、`parseSsoClients`）放在 `envs/` 下供三份 env 复用。
- 依赖方向：`envs/*` 仅依赖 `cors-origins.ts` / `sso-clients.ts` 等纯解析函数，不反向依赖 `config.service`；`config.service` 仅依赖 `interfaces/config.interface.ts` 的类型，不感知环境变量来源。
- 扩展点：新增配置需同步更新 `interfaces/config.interface.ts` 的 `Config` 联合、`ConfigService` 的 getter 以及 `config.module.ts` 中的 Zod `baseSchema`，三者构成契约门禁。
