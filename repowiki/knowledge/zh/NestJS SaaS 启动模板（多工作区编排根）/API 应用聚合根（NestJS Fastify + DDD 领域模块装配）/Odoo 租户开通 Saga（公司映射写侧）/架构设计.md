模块遵循 `api/application/infrastructure` 三层划分：
- `api/odoo-provisioning.module.ts` 为 NestJS 装配入口，仅注册 saga、`OdooJsonClient` 与 `ODOO_COMPANY_GATEWAY` Symbol 端口绑定，由 `feature-loader.ts` 运行期探测加载。
- `application/odoo-provisioning.saga.ts` 是 `@EventsHandler(OrganizationStatusTransitionedEvent)` 处理器，仅响应 `pending_approval → active` 的首次开通；通过 `OrganizationOdooBindingReader/Writer`（来自 `@core/saas-kit`）持久化意图（`provisioning`→`ready`/`failed`），保证崩溃恢复幂等。
- `infrastructure/odoo-company-gateway.ts` 定义 `OdooCompanyGateway` 接口与 `Symbol('ODOO_COMPANY_GATEWAY')` 端口，`infrastructure/odoo-json-company.gateway.ts` 提供基于 `OdooJsonClient.executeKw` 的 JSON-RPC 适配；其中 `findCompanyIdByName`/`createCompany` 为真实现，`applyLocalizationBaseline`/`provisionAdministrator` 为带 warn 日志的骨架占位，留待联调窗补实。
依赖方向单向：saga → gateway 端口 → JSON-RPC 客户端；Saga 不直接依赖 Odoo 模型或 `@core` 外部副作用，仅通过 published port 与只读 RPC feature 解耦。
