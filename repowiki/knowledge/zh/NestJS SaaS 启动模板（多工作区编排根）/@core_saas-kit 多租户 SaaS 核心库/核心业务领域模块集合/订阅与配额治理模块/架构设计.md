模块按 DDD + CQRS 分层组织：
- `domain/`：纯领域层，包含状态机 `subscription-lifecycle.ts`（基于 `organization-plans.ts` 的 `SubscriptionStatus` 单源联合类型 + `TRANSITIONS` 迁移表 + `canTransition` 判定）、事件定义（`subscription-created` / `subscription-bootstrapped` / `subscription-status-transitioned`）、仓储端口 `SubscriptionRepository`（通过 `SUBSCRIPTION_REPOSITORY` Symbol 注入，不暴露 tenantId，由 adapter 从 ALS 注入）以及外部依赖端口 `CustomerProvisioner` / `SubscriptionLifecyclePort`。
- `application/`：CQRS 应用层，命令 `CreateSubscriptionCommand` 经 `CreateSubscriptionCommandHandler` 编排：解析档位 → 调用 `CustomerProvisioner` 建立 provider 映射 → 写入订阅行 → 返回 `QuotaService.snapshot`；查询 `GetCurrentSubscriptionQuery` 经对应 handler 读取 read-model；`read-models/subscription.read-model.ts` 作为投影输出契约。
- `quota/`：配额子域，`organization-plans.ts` 集中声明 `FREE_PLAN` / `pro` / `enterprise` 档位及 `SubscriptionStatus` 联合类型；`quota.vo.ts` 的 `Quota` VO 封装非负整数不变量；`quota.service.ts` 聚合当前活跃订阅、成员计数与限额比较，对外暴露 `checkSeats` / `snapshot`；`quota.guard.ts` 作为 Nest Guard 在路由层做 opt-in 配额拦截并抛出 402；`quota.decorator.ts` 提供 `@Quota({ seats })` 元数据；`quota.store.ts` 通过 `QUOTA_STORE` token 抽象读侧数据源。
- 横向开关：handler 通过 `@Optional()` 注入 `EVENT_STORE` / `UNIT_OF_WORK` / `DOMAIN_EVENT_PUBLISHER` / `ES_TRUTH_SOURCE_SUBSCRIPTIONS`，在 truthSource=false 时走纯 CRUD 旧路径，true 时走 ES R4c 真相源路径（新建即 append `subscription.created` 流起点，UoW 包裹 insert+append 同事务）。
