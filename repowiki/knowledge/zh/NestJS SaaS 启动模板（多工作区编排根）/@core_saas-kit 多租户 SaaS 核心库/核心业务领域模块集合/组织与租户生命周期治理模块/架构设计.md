模块按职责拆为两个子目录：
- `lifecycle/`：核心领域层。`organization-lifecycle.ts` 提供纯函数（`TENANT_STATUS` 枚举 + `canTransition` / `isTenantBlocked`）作为状态机真相源；`tenant-status.service.ts` 与 `user-status.service.ts` 是 NestJS `@Injectable()` 服务，分别通过 `TenantStatusStore` / `UserStatusStore` 端口（`tenant-status.store.ts`、`user-status.store.ts`，以 `Symbol` token 注入）访问持久化，并借助 `UNIT_OF_WORK` 将 upsert 与 `DomainEventPublisher.publishAll` 包入同一事务，产出 `OrganizationStatusTransitionedEvent` / `UserStatusTransitionedEvent`（位于 `events/`，继承 `shared-kernel/domain/domain-event.DomainEvent`）。`organization-odoo-binding*.ts` 与 `organization-bootstrapped.event.ts` 等负责与 Odoo 的绑定与引导事件。
- `visibility/org-visibility.ts`：纯函数策略常量（`ORG_VISIBILITY.SHARED|ISOLATED`），供全局 filter 在租内追加组织维隔离过滤。
依赖方向单向向外：本模块仅依赖 `shared-kernel`（domain-event、event-publisher.port、unit-of-work.port、request-context），不反向依赖任何实现层，持久化细节经 Store 端口倒置由上层装配。
