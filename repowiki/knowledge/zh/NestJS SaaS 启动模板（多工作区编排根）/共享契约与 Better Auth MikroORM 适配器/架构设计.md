本模块由三个相互独立的子包组成，依赖方向单向：`@saas/api-contract` → `@saas/contracts`，`ba-mikro-adapter` 独立。

- `libs/contracts`（`@saas/contracts`）：纯 zod schema + 派生类型单源，按 `event/`、`request/`、`response/` 三域组织 barrel 导出；`envelope.ts` 定义 HTTP 成功信封与错误响应结构，`strict.ts` 提供严格对象构造器；零依赖 `@core`，仅声明 `zod` peerDependency，供前端与后端共同消费以达成「运行时校验 / 编译期类型 / OpenAPI 文档」三态同源。
- `libs/api-contract`（`@saas/api-contract`）：基于 `@orpc/contract` 的 oRPC 契约先行层。`base.ts` 暴露 `oc`（与 `apps/api` 侧 `common/orpc/orpc.ts` 同源），各域 `<domain>.contract.ts` 用 `oc.procedure` 声明 procedure 契约；`app-router.contract.ts` 通过 `PUBLIC_APP_ROUTER_SPEC` 把 56 个公共 procedure 聚合成嵌套树并 `oc.router()` 派生 `AppRouterContract` 类型锚点，被 `api-client` 与 `apps/web` 用作客户端类型入口；`app-router.contract.test.ts` 深走该树做恒等对拍，防止 router 与实存契约漂移。
- `libs/ba-mikro-adapter`（`@okee/ba-mikro-adapter`）：实现 Better Auth 官方 `createAdapterFactory` 规范的自定义 DBAdapter，适配 MikroORM v7。核心文件 `mikro-auth-adapter.ts` 导出工厂 `mikroAuthAdapter(orm)`，内部用 `AsyncLocalStorage` 在 `transaction` 回调中透传事务级 `em`，所有 CRUD 方法通过 `em.execute` 直接执行原生 SQL（camelCase 列名 + 双引号标识符），补齐社区包缺失的 `consumeOne`/`incrementOne`/`transaction` 能力，并以 `supportsDates:false` 让 BA factory 代劳 Date↔ISO 串转换。

三个包均使用 Nest CLI (`nest-cli.json`) + TypeScript 构建，产物位于各自 `dist/`，并通过 `package.json` 的 `exports` + `typesVersions` 暴露子路径类型。
