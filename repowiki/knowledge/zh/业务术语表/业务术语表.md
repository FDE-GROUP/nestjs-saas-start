### 三段论
- 定义：项目宪法级设计意图：Ⅰ治理归 SaaS（准入前数据治理）、ⅡERP 能力不重建（Odoo 已有者仅集成）、Ⅲ补位归 SaaS（控制面/数据沉淀/AI 等）。任何新需求按 ②→①→③ 顺序裁断归属，Ⅱ 具一票否决力。
- 别名：设计意图三段论、功能归属判据

### features/
- 定义：`apps/api/src/features/<name>/` = 第三方服务集成专属区，承载无自有领域的对接功能（防腐层薄适配 + 类型化端点），与 `modules/`（自有领域限界上下文）双向隔离；内部层形 `{application, infrastructure, api}`，禁设 `domain/`。
- 别名：features 目录、第三方集成区

### binding
- 定义：SaaS 组织与 Odoo `res.company` 之间的平行映射对象，字段含 `odooCompanyId`、`state(PENDING/PROVISIONING/READY/FAILED)`、`lastReconciledAt`、`snapshot(odooCompanyName)`、`failureReason`；状态机与重试策略放 `@core` 契约 + features 实现。
- 别名：租户绑定、公司绑定

### provisioning saga
- 定义：approve-organization 后触发的异步状态机：PENDING → COMPANY_CREATED → CHART_APPLIED（按国别装 l10n 科目表）→ USERS_PROVISIONED（管理员入 company 的 allowed_companies）→ READY，任一步失败进 FAILED + 重试/doctor。
- 别名：开通流程、公司开通

### canUseOdoo
- 定义：裁决函数：`org.status === active ∧ binding.state === READY` 才允许访问 Odoo 能力；统一用于 apps/web 面板、SSO 路由、RPC 读面三处卡点，避免口径漂移。
- 别名：Odoo 可用性裁决

### 孤儿公司
- 定义：Odoo 有 `res.company`、SaaS 无绑定的异常态（运维旁路直接建司或建完公司后写 binding 失败），需 doctor 低频反向审计告警。
- 别名：orphan company

### 悬空绑定
- 定义：SaaS 有 binding、Odoo 公司不存在或已归档的异常态，由 doctor 正向核验（`res.company` read 对拍）发现。
- 别名：dangling binding

### 金标准对拍
- 定义：交付物验收口径：全新容器自 bake 出修复 → 真实浏览器端到端验证（SSO 一键闭环、后台有内容、deny-by-default 未破），而非仅 shell 或旧镜像复测。
- 别名：交付镜像端到端、全链真跑对拍

### 切片 F/G
- 定义：demo 方案文档中的可审切片编号：F = 浏览器一键登录闭环（node 内置零依赖反代同源门）；G = demo 内置 apps/web 同域（`:7009/app/`）+ 门导航。
- 别名：切片F、切片G

### 门 B/C
- 定义：AGENTS 铁律下的审计门禁：门 B = 架构/方案审计（改 auth 面须人签）；门 C = CI/发布变更审计（workflow_dispatch 手动触发）。
- 别名：审计门B、发布门C
