## 引言
本文件系统性梳理“审批制租户”的生命周期管理，覆盖状态机、命令处理器、状态存储与一致性、审计日志、以及订阅与配额集成。目标是让非技术读者也能理解从提交申请到平台审批、拒绝、暂停、恢复、软删除和硬删除的完整流程，并掌握各阶段的 API 行为与错误策略。

## 项目结构
围绕租户生命周期，代码按领域分层组织：
- 领域纯函数与状态机定义位于核心库；
- 应用层命令处理器封装业务规则与审计；
- 基础设施层提供状态存储、审计日志与事件持久化；
- 订阅与配额子系统通过事件与租户状态联动。

## 核心组件
- 状态机纯函数：定义租户状态枚举、拦截判定与合法迁移表。

## 详细组件分析

### 状态机与拦截策略
- 状态集合：pending_approval、active、suspended、deleted。
- 拦截策略：仅显式处于 pending_approval、suspended、deleted 时阻断访问；无状态记录视为不阻断（兼容存量）。
- 迁移表：
  - pending_approval → active / deleted
  - active → active（幂等）/ suspended / deleted
  - suspended → active / deleted
  - deleted 终态不接受任何迁移

```mermaid

ResolveFrom --> Lookup["查迁移表 TRANSITIONS[from]"]
Lookup --> Check{"to 是否在允许列表"}
Check --> |是| Allow["返回 true"]
Check --> |否| Deny["返回 false"]
```

### 租户状态服务与一致性
- 读接口：read、isActive、isBlocked。
- 迁移 transition：
  - 在 UnitOfWork 内执行，保证写回与事件发布的原子性。
  - 先校验 tenantExists，不存在返回 not-found。
  - 用 canTransition 严格裁决，非法返回 illegal。
  - 成功后 upsert 写入 tenant.status，并发布 OrganizationStatusTransitionedEvent。
- 审计：由上层处理器统一落审计，服务本身不直接写审计。

```mermaid
sequenceDiagram
participant Handler as "命令处理器"
participant Service as "TenantStatusService"
participant Store as "MikroTenantStatusStore"
participant Events as "DomainEventPublisher"
Handler->>Service : transition(tenantId, target, options)
Service->>Store : tenantExists(tenantId)
Store-->>Service : boolean
alt 不存在
Service-->>Handler : {kind : 'not-found'}
else 存在
Service->>Store : readStatus(tenantId)
Store-->>Service : previous
Service->>Service : canTransition(previous, target)
alt 非法
Service-->>Handler : {kind : 'illegal', from, to}
else 合法
Service->>Store : upsert(tenantId, target)
Service->>Events : publishAll([OrganizationStatusTransitionedEvent])
Service-->>Handler : {kind : 'ok', previous, status}
end
end
```

### 命令处理器与业务规则

#### 审批通过（pending_approval → active）
- 入口：ApproveOrganizationCommandHandler。
- 逻辑：委托 governedOrganizationTransition，调用 TenantStatusService.transition 目标为 active。
- 结果：
  - not-found → null（控制层转 404）。
  - illegal → 审计 + 409。
  - ok → 审计 + 返回组织应用读模型。

```mermaid
sequenceDiagram

participant G as "governedOrganizationTransition"

participant A as "PlatformAuditService"

S-->>G : result(ok/not-found/illegal)
alt not-found
G-->>C : null
else illegal
G->>A : logOrganizationGovernance('approve', orgId, operatorId, {error : 'illegal_transition'})
G-->>C : 抛出 409

G->>A : logOrganizationGovernance('approve', orgId, operatorId, {from,to})

end
```

## 故障排查指南
- 非法迁移 409：
  - 常见原因：对已 deleted 的租户再次迁移、从非 allowed 前态迁移。
  - 处理：确认当前状态与目标状态是否符合迁移表；查看审计日志中的 error=illegal_transition。
- 目标不存在 404：
  - 常见原因：租户本体不存在或已被硬删。
  - 处理：确认租户是否存在；硬删后幂等返回 null。
- 驳回失败：
  - 常见原因：申请非 pending 状态。
  - 处理：查看审计日志 error=not_pending；仅 pending 可申请驳回。
- 硬删未生效：
  - 常见原因：并发被其他事务先执行；或租户不在 deleted 终态。
  - 处理：确认状态为 deleted；重试幂等；审计日志可能记录 already_gone。

### 平台侧治理端点（示例）
- 审批通过
  - 方法：POST /platform/organizations/:id/approve
  - 入参：operatorId（平台操作者）

  - 失败：404（租户不存在）、409（非法迁移）
- 驳回申请
  - 方法：POST /platform/organizations/:id/reject
  - 入参：operatorId
  - 成功：返回布尔值（是否移除）
  - 失败：404（不存在）、409（非 pending）
- 暂停租户
  - 方法：POST /platform/tenants/:id/suspend
  - 入参：operatorId
  - 成功：返回租户治理回执
  - 失败：404（不存在）、409（非法迁移）
- 恢复租户
  - 方法：POST /platform/tenants/:id/resume
  - 入参：operatorId
  - 成功：返回租户治理回执
  - 失败：404（不存在）、409（非法迁移）
- 软删租户
  - 方法：POST /platform/tenants/:id/delete
  - 入参：operatorId
  - 成功：返回租户治理回执
  - 失败：404（不存在）、409（非法迁移）
- 硬删租户
  - 方法：DELETE /platform/tenants/:id/permanent
  - 入参：operatorId
  - 成功：返回 {tenantId, purgedOrgs, purgedEvents}
  - 失败：404（不存在/已硬删）、409（非 deleted 终态）
